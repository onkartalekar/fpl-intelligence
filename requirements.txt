# FPL Intelligence has been stdlib-only since Phase 0 (see IMPLEMENTATION_PLAN.md's
# "Dependencies" rule). numpy is a single, deliberate, narrow exception: issue #65's
# ridge-regression minutes/start-probability shadow challenger uses numpy's closed-form
# ridge solve ((X^T X + lambda I)^-1 X^T y) in the offline weight-fitting script
# (scripts/fit_ml_minutes_weights.py) rather than reimplementing linear-algebra primitives
# by hand. The fitted weights are checked into config/ml-minutes-weights.json; the live
# module that applies them at refresh time (src/fpl_intel/ml_minutes.py) is a plain
# weighted sum and does not import numpy itself. See MODEL.md and
# plans/issue-65-ml-shadow-model.md for the full rationale.
numpy>=2.0,<3.0

# Second deliberate, narrow exception (issue #240): the deadline reminder email's Starting XI
# diagram used to be inline <svg>, which Gmail's HTML sanitizer strips down to garbled unstyled
# text (see src/fpl_intel/notifications/pitch_image.py's module docstring for the full repro).
# Rendering it server-side as a real PNG and serving it as a plain <img> is the fix -- every
# mainstream client, Gmail included, reliably displays a plain raster image, unlike inline SVG or
# a data-URI. There is no stdlib way to rasterize shapes/text into an image; Pillow does the
# drawing and PNG encoding. Used only by pitch_image.py (both the reminder script, to build the
# image URL, and the dashboard server, to render it on request) -- no other module imports it.
Pillow>=10.1,<12.0
